> 이 문서에 있는 계산된 필드를 **Looker Studio에 미리 만들어두면** 모든 차트에서 재사용할 수 있습니다.
> 데이터 소스: BigQuery `olist-team-analysis.olist_analysis.*`

## 0. 사용 전 확인 — 컬럼 이름 검증

각 테이블의 실제 컬럼명이 아래 가정과 다를 수 있습니다. **처음 한 번 BigQuery 콘솔에서 직접 확인**해주세요.

```sql
-- BigQuery 콘솔에서 실행
SELECT column_name, data_type
FROM `olist-team-analysis.olist_analysis.INFORMATION_SCHEMA.COLUMNS`
WHERE table_name IN ('t_orders_summary', 't_order_items')
ORDER BY table_name, ordinal_position;
```

이 결과로 나온 컬럼명을 아래 공식과 대조해서, 다르면 공식을 수정해주세요. (예: `is_delayed` 컬럼이 이미 있으면 새로 만들지 않고 그대로 사용)

## 2. 미리 만들어둘 계산된 필드 — `t_orders_summary` 기준

### 2-1. 배송 지연 관련

```
필드 이름: is_delayed
공식:      CASE WHEN delivered_customer_date > estimated_delivery_date THEN 1 ELSE 0 END
설명:      이 주문이 약속일보다 늦게 도착했는가? (1=지연, 0=정시)
사용 차트: KR4 게이지, 주별 지연율, 카테고리별 지연율
```

```
필드 이름: delay_days
공식:      DATE_DIFF(delivered_customer_date, estimated_delivery_date, DAY)
설명:      약속일보다 며칠 늦었는가? (음수면 일찍 도착)
사용 차트: 배송 소요일 분포 히스토그램
```

```
필드 이름: delivery_days
공식:      DATE_DIFF(delivered_customer_date, purchase_timestamp, DAY)
설명:      구매부터 도착까지 총 며칠이 걸렸는가?
사용 차트: 평균 배송일 카드, Total Lead Time
```

### 2-2. 재구매 관련

```
필드 이름: is_repeat_customer
공식:      CASE WHEN customer_order_seq >= 2 THEN 1 ELSE 0 END
설명:      이 주문이 같은 고객의 2번째 이상 주문인가?
사용 차트: KR3 재구매 비중 게이지, 카테고리별 재구매율
주의:      이미 t_orders_summary에 같은 컬럼이 있다면 신규 생성 X
```

```
필드 이름: is_repeat_customer_unique
공식:      CASE WHEN max_customer_order_seq >= 2 THEN 1 ELSE 0 END
설명:      이 고객이 평생 2번 이상 구매했는가? (KR1 계산용)
주의:      max_customer_order_seq 컬럼이 없으면 BigQuery에서 미리 집계 필요.
           대안 — 차트에서 '고유 customer_unique_id 기준 COUNT DISTINCT' 사용
```

### 2-3. 평점 관련

```
필드 이름: is_low_rating
공식:      CASE WHEN review_score IN (1, 2) THEN 1 ELSE 0 END
설명:      저평점(1~2점) 리뷰인가?
사용 차트: KR5 저평점 비중 게이지, 카테고리별 저평점
```

```
필드 이름: is_high_rating
공식:      CASE WHEN review_score = 5 THEN 1 ELSE 0 END
설명:      5점 만점 리뷰인가? (P2 핵심 통찰용)
사용 차트: 평점별 재구매율
```

### 2-4. 시간 관련

```
필드 이름: purchase_year_month
공식:      FORMAT_DATE('%Y-%m', DATE(purchase_timestamp))
설명:      "2017-08" 형태의 월 단위 그룹핑
사용 차트: 월별 KR 추이, 월별 지연율 추이
```

```
필드 이름: purchase_quarter
공식:      FORMAT_DATE('%Y-Q%Q', DATE(purchase_timestamp))
설명:      "2017-Q3" 형태의 분기 그룹핑
사용 차트: 분기별 비교가 필요할 때
```

### 2-5. BF (Black Friday) 관련

```
필드 이름: is_bf_2017
공식:      CASE WHEN DATE(purchase_timestamp) BETWEEN '2017-11-24' AND '2017-11-26' THEN 1 ELSE 0 END
설명:      2017년 BF 기간(11/24~26) 주문인가?
사용 차트: BF cohort 카드, BF 코호트 추적
```

```
필드 이름: days_since_purchase
공식:      DATE_DIFF(CURRENT_DATE(), DATE(purchase_timestamp), DAY)
설명:      구매로부터 며칠 지났나 (코호트 분석용 보조)
주의:      코호트 차트는 보통 BigQuery에서 미리 만든 후 Looker로 가져오는 게 편함.
           아래 BigQuery 보조 SQL 참고.
```

## 3. 미리 만들어둘 계산된 필드 — `t_order_items` 기준

### 3-1. 카테고리 표시

```
필드 이름: category_kr
공식:      IFNULL(product_category_name_english, '미분류')
```

## 4. KR 계산식 (차트에 입력하는 측정항목)

대부분의 차트는 위 계산된 필드를 그대로 끌어 쓰면 됩니다. 측정항목 칸에 넣을 때 **집계 방식**을 선택해주세요.

| KR | Looker 측정항목 입력 | 집계 방식 |
|----|--------------------|----------|
| KR1 재구매율 | `customer_unique_id` 기준 별도 계산 (아래 ★ 참고) | — |
| KR2 주문수/인 | `order_id` COUNT / `customer_unique_id` COUNT_DISTINCT | 비율 |
| KR3 재구매 비중 | `is_repeat_customer` SUM / `order_id` COUNT | 비율 |
| KR4 지연율 | `is_delayed` AVG | 평균 (또는 SUM/COUNT) |
| KR5 저평점 | `is_low_rating` AVG | 평균 |

### ★ KR1 재구매율 — 가장 까다로운 지표

KR1은 "고객 단위" 계산이라 단순 평균으로 안 나옵니다. 두 가지 방법 중 택1:

**방법 A. BigQuery에서 미리 집계 테이블 만들기 (권장)**

```sql
-- 새 테이블 t_customer_summary 생성
CREATE OR REPLACE TABLE `olist-team-analysis.olist_analysis.t_customer_summary` AS
SELECT
  customer_unique_id,
  COUNT(DISTINCT order_id) AS order_count,
  CASE WHEN COUNT(DISTINCT order_id) >= 2 THEN 1 ELSE 0 END AS is_repeat,
  MIN(DATE(purchase_timestamp)) AS first_purchase_date,
  MAX(DATE(purchase_timestamp)) AS last_purchase_date
FROM `olist-team-analysis.olist_analysis.t_orders_summary`
WHERE order_status = 'delivered'
GROUP BY customer_unique_id;
```

이 테이블을 Looker에 추가 데이터 소스로 연결하면, KR1 게이지는 단순히 `is_repeat AVG` 로 끝납니다.

**방법 B. Looker 계산된 필드만으로 처리 (덜 정확)**

```
필드 이름: kr1_재구매율_근사
공식:      COUNT_DISTINCT(CASE WHEN customer_order_seq >= 2 THEN customer_unique_id END)
           / COUNT_DISTINCT(customer_unique_id)
주의:      Looker 집계 함수 동작 방식 때문에 정확한 값이 안 나올 수 있음.
           발표 직전 검증 필수.
```

> 발표용이라면 방법 A를 추천합니다. BigQuery에서 한 번 만들면 끝나고, 결과값도 확실합니다.

## 5. BigQuery 보조 SQL — 코호트 리텐션 (P3에서 사용)

P3 TF3 영역의 코호트 리텐션 히트맵은 BigQuery에서 미리 가공한 후 Looker로 끌어오는 게 가장 안정적입니다.

```sql
-- 새 테이블 t_cohort_retention 생성
CREATE OR REPLACE TABLE `olist-team-analysis.olist_analysis.t_cohort_retention` AS
WITH first_purchase AS (
  SELECT
    customer_unique_id,
    DATE_TRUNC(MIN(DATE(purchase_timestamp)), MONTH) AS cohort_month
  FROM `olist-team-analysis.olist_analysis.t_orders_summary`
  WHERE order_status = 'delivered'
  GROUP BY customer_unique_id
),
all_purchases AS (
  SELECT
    o.customer_unique_id,
    fp.cohort_month,
    DATE_TRUNC(DATE(o.purchase_timestamp), MONTH) AS purchase_month,
    DATE_DIFF(DATE(o.purchase_timestamp), fp.cohort_month, MONTH) AS month_number
  FROM `olist-team-analysis.olist_analysis.t_orders_summary` o
  JOIN first_purchase fp USING (customer_unique_id)
  WHERE o.order_status = 'delivered'
)
SELECT
  cohort_month,
  month_number,
  COUNT(DISTINCT customer_unique_id) AS active_customers
FROM all_purchases
GROUP BY cohort_month, month_number;
```

이 테이블을 Looker에 연결하고 피벗 테이블로 그리면 코호트 히트맵이 됩니다.
- 행: `cohort_month`
- 열: `month_number`
- 값: `active_customers / 첫 달 active_customers` (리텐션율)

## 6. 검증용 SQL — 슬라이드 핵심 수치 재확인

대시보드에 보이는 값이 발표 슬라이드 §1-3 표와 다르면 곤란합니다. 발표 전 한 번 검증해주세요.

```sql
-- KR1 재구매율 (3.00% 나와야 정상)
SELECT
  COUNT(DISTINCT CASE WHEN order_count >= 2 THEN customer_unique_id END)
  / COUNT(DISTINCT customer_unique_id) * 100 AS kr1_재구매율_pct
FROM `olist-team-analysis.olist_analysis.t_customer_summary`;

-- KR3 재구매 주문 비중 (6.13% 나와야 정상)
SELECT
  AVG(CASE WHEN customer_order_seq >= 2 THEN 1 ELSE 0 END) * 100 AS kr3_재구매비중_pct
FROM `olist-team-analysis.olist_analysis.t_orders_summary`
WHERE order_status = 'delivered';

-- KR4 첫 구매 배송 지연율 (8.16% 나와야 정상)
SELECT
  AVG(CASE WHEN delivered_customer_date > estimated_delivery_date THEN 1 ELSE 0 END) * 100
    AS kr4_첫구매지연율_pct
FROM `olist-team-analysis.olist_analysis.t_orders_summary`
WHERE order_status = 'delivered'
  AND customer_order_seq = 1;

-- KR5 첫 구매 저평점 비중 (12.82% 나와야 정상)
SELECT
  AVG(CASE WHEN review_score IN (1,2) THEN 1 ELSE 0 END) * 100 AS kr5_저평점_pct
FROM `olist-team-analysis.olist_analysis.t_orders_summary`
WHERE order_status = 'delivered'
  AND customer_order_seq = 1
  AND review_score IS NOT NULL;
```

각 쿼리 결과가 슬라이드 핵심 수치와 다르면, 차트도 그 값에 맞춰 표시되도록 필터·계산식을 다시 점검해야 합니다.
