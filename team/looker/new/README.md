## 왜 다시 만드는가

발표 일정이 7일 남은 시점(5/2 → 5/9)에서 기존 대시보드(7~8페이지)는 너무 양이 많습니다.
슬라이드 구성안 v2에서 Looker는 "발표 시 패스 · Q&A·후속 접근용 참고 자료"로 포지셔닝이 바뀌었기 때문에, **3페이지로 압축**해서 슬라이드 내러티브에 정확히 맞춥니다.

---

## 3페이지 구조

```
P1. 전사 현황 ──┐
"재구매 구조가  │  슬2(결론) · 슬3(3축 신호등) · 슬4(RFM) 의 데이터 백업
 없다"          │  → 청중이 처음 펼쳤을 때 발표 결론과 같은 충격을 받는다

P2. 핵심 통찰 ──┐
"5점=배송,      │  슬5(KPI Tree) · 슬6(원인 분해) · 슬7(피크) · 슬8(Finding) 백업
 저평점=4팀     │  → 통찰의 근거(왜 TF 3개로 묶었는가)를 데이터로 보여준다
 분산"          │

P3. TF별 추적 ──┐
"3개 TF가 어떻게│  슬11(이중 트랙) · 슬25(기대효과 3열 시계열) 백업
 KR을 책임지나" │  → TF별 책임 KR 추적 — TF3에 가장 큰 비중
```

## 발표 슬27(참고 슬라이드) 연결 방법

발표 슬라이드 27장에 다음을 넣습니다:

1. Looker 대시보드 공유 URL (View 권한)
2. URL을 QR 코드로 변환 (qr-code-generator.com 등)
3. 캡션: *"발표에서 다 보여드리지 못한 데이터는 이 대시보드에 모아뒀습니다"*
