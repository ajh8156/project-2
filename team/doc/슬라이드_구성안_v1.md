## 스토리텔링 원칙 — 연역적 구조

코치 피드백 반영: **결론 먼저 → 근거 연결 → 결론 재확인**

```
결론 먼저 (슬2):
  "Olist에는 재구매 구조가 없습니다. 우리는 재구매 구조를 만들어야 합니다."

근거 연결 고리:
  데이터를 보면 97%가 이탈한다 (EDA)
  → 수식상 병목은 구매 빈도다 (KPI Tree)
  → 여정상 Retention 단계가 무너지고 있다 (AARRR)
  → 원인은 배송·리뷰·CRM 부재 3가지다 (가설 검증)
  → 따라서 각 팀이 이 3가지를 잡아야 한다 (팀별 액션)

최종 결론 (슬 마지막):
  "이를 실행하면 재구매율 3% → 4.5% 달성 가능"
```

각 막 전환 시 연결 멘트:

| 막 전환 | 연결 멘트 |
|---------|---------|
| Act1 → Act2 | "왜 그런지, 데이터로 확인해봤습니다" |
| Act2 → Act3 | "수식으로 병목을 좁혀봤습니다" |
| Act3 → Act4 | "3가지 Finding을 데이터로 검증했습니다" |
| Act4 → Act5 | "원인이 확인됐습니다 → 팀별 해결책입니다" |
| Act5 → Act6 | "첫 검증 기회는 올해 BF입니다" |
| Act6 → Act7 | "이렇게 달라집니다 → 그래서 우리는 이것을 해야 합니다" |

## 팀 파트 구조 — 논의 필요 사항

---

### 논의 1: 협업을 어떻게 보여줄 것인가

#### 방식 A: 팀-퍼스트 + 협업 화살표 *(현재 추천)*

각 팀이 자기 슬라이드 3장을 갖고, 슬라이드 2에서 협력 팀을 명시.
Act 5 시작 전 인트로 1장으로 전체 협업 지도를 보여줌.

```
[인트로] 5팀 협업 지도 + AARRR 담당 + TF 구역
[팀별 3슬라이드] 지표 → 병목 해결(+협력 화살표) → 산출물
[마무리] 협업 매트릭스 1장
```

- 장점: 각 팀원이 자기 파트 발표 가능 / 협업도 명시
- 단점: 슬라이드 많음 (5팀×3 + 인트로 + 매트릭스 = 18장)

#### 방식 B: 병목-퍼스트 (TF 중심)

팀이 아닌 해결할 병목 3개 기준으로 묶음.

```
[병목 1: 배송 품질]   Logistics + Seller Ops → KR4·KR5
[병목 2: 첫 경험]     Product + CX → KR5
[병목 3: 재구매 유도] CRM + MD → KR1·KR2·KR3
```

각 병목 파트: 3슬라이드 (목표 → 협력 전략 → 산출물)

- 장점: 협업이 가장 자연스럽게 보임 / 연역 흐름과 일치
- 단점: 개별 팀 기여가 묻힐 수 있음 / 팀원 파트 구분 어려울 수 있음

#### 방식 C: 타임라인-퍼스트

3개월 / 6개월 / 12개월 시기별로 슬라이드 구성.

- 장점: 로드맵 느낌 / 실행 타이밍 명확
- 단점: 목업 보여주기 어려움

**추천 이유 (A안)**: 팀원 각자 발표 + 협업도 표현 가능. 시간 부족 시 B안으로 9장 압축 가능.
